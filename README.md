# editmatker — 자동 하이라이트 에딧 메이커

**[▶ 앱 실행하기](https://editmatker.vercel.app)**

주제와 특징만 적으면 YouTube·Reddit에서 관련 영상을 알아서 찾고, 하이라이트 장면만 뽑아 비트에 맞춰 편집한 에딧 영상을 만들어 줍니다. 편집과 렌더링은 모두 브라우저 안에서 이루어지고 API 키가 필요 없습니다. YouTube 영상을 쓰려면 내 컴퓨터에서 [로컬 도우미](#youtube-로컬-도우미-pc-전용)를 켜 두면 됩니다.

```
주제: 아폴로 11호
특징: 웅장하고 시네마틱하게, 로켓 발사, 슬로우모션
→ 30초 · 9:16 · 90 BPM 시네마틱 에딧 (.mp4 / .webm)
```

## 작동 방식

1. **주제 해석과 검색어 확장** — Wikidata에서 주제를 찾아(못 찾으면 한국어·영어 Wikipedia 검색으로 다시 찾음) 입력값 하나가 아니라 여러 검색어를 만듭니다.
   - 한국어 이름과 영어 이름 (+ 특징에서 뽑은 영어 키워드)
   - 다른 이름(별칭) — 예: `Sonny`, `쏘니`
   - 관련 주제 — Wikidata의 소속 팀·그룹·구성원·종목·장르·대표작 등과 Wikipedia의 비슷한 문서
   - 화면에 실제로 쓴 검색어가 표시되고, 넓힌 검색어로 찾은 영상일수록 뒤로 밀립니다.
2. **영상 검색** — 영상 라이선스 선택에 따라 찾는 곳이 달라집니다.
   - **모든 공개 영상**(기본): **YouTube**와 **Reddit**(Reddit에 올라온 영상과 공유된 YouTube 링크)을 **한국어와 영어로 함께** 검색해(예: `손흥민` + `Son Heung-min goal`, 영어 이름은 Wikidata에서 가져옴) 먼저 찾고, Wikimedia Commons·Internet Archive·스톡 영상(Pexels·Pixabay·Mixkit)으로 보충합니다. 라이선스와 관계없이 쓰므로 영상마다 "재사용 허가 확인 필요" 표시가 붙습니다.
   - **재사용 가능만**: Wikimedia Commons·Internet Archive에서 2차 편집이 허용되는 **Public domain · CC0 · CC BY · CC BY-SA** 영상과 무료 스톡 영상만 씁니다.
   - **스톡 영상**: [Pexels](https://www.pexels.com/license/)·[Pixabay](https://pixabay.com/service/license-summary/)·[Mixkit](https://mixkit.co/license/#videoFree)은 무료로 수정·상업 이용이 가능한 자체 라이선스라 두 모드 모두에서 씁니다. 영어 이름으로 검색하고, 제목·태그에 주제 이름이 있는 영상만 씁니다(풍경·도시·사물 주제에 잘 맞고, 인물은 거의 없음). Pexels·Pixabay는 무료 API 키가 필요해 **영상 라이선스 → 스톡 영상 API 키**에 넣거나(이 기기에만 저장) Vercel 환경 변수 `PEXELS_API_KEY`, `PIXABAY_API_KEY`를 설정하세요. Mixkit은 키 없이 됩니다.
   - **관련성 확인**: 넓힌 검색어로 찾았더라도, 제목·태그·채널에 주제 이름(한국어·영어·별칭, 띄어쓰기·기호·순서 차이 허용)이 실제로 나오는 영상만 씁니다. 주제의 Commons 분류나 Wikidata 대표 영상은 이름이 없어도 씁니다. 관련 주제는 항상 주제 이름과 함께 검색합니다(예: `Son Heung-min Tottenham`). 이름이 나오는 영상이 없으면 엉뚱한 영상으로 만들지 않고 "찾지 못했어요"라고 알려 줍니다.
3. **하이라이트 분석** — 영상을 내려받아(파일당 최대 150MB, 가능하면 480p) 프레임마다 움직임·색감·밝기·소리 세기와 장면 전환을 측정합니다. 특징에 맞춘 가중치로 점수를 매기고, 장면 전환이 끼지 않은 가장 좋은 구간을 골라냅니다.
4. **비트 편집** — 인트로 → 드롭 → 아웃트로 구조로 컷을 박자에 맞춰 배치합니다. 가장 좋은 장면은 드롭에 들어가고, 같은 영상이 연달아 나오지 않게 섞습니다.
5. **음악** — 분위기에 맞는 비트를 Web Audio로 직접 작곡합니다(저작권 걱정 없음). 내 음악 파일을 넣으면 BPM·박자 위치·드롭 지점을 자동으로 찾아 맞춥니다.
6. **렌더링** — 캔버스에서 색 보정, 줌 무빙, 비트 펄스·흔들림, 플래시 컷, 글리치, 슬로모션, 필름 그레인, 레터박스, 타이틀을 입혀 실시간으로 녹화합니다. 영상 끝에는 출처 크레딧 카드가 자동으로 들어갑니다.

### 내 영상으로 편집

**내 영상으로 편집**에 편집할 영상을 직접 올릴 수 있습니다(최대 8개). 영상을 찾기 어려운 주제나 내가 찍은 영상으로 에딧을 만들 때 쓰세요.

- **주제를 비우고 특징·분위기만 적어도** 됩니다. 하나로 정하지 않고, 문장 속 **구체적인 대상**(사람·그룹·팀·장소·작품 등, Wikidata로 확인)은 모두 주제로(최대 3개, 같은 비중) 쓰고, **일반적인 말**(무대·바다·골 등)은 공통 특징으로 주제와 함께 검색하고 제목에 나오면 우선합니다. 예: "뉴진스 해린 무대 장면 위주로" → 주제 뉴진스·해린, 공통 특징 무대. 대상이 없으면(스타일만 적은 경우) 주제를 적어 달라고 알려 줍니다.
- 올린 영상으로 고를 때도 하나로 정하지 않습니다: 파일 이름은 절반 이상에 공통으로 나오는 말(가장 많은 말이 주제, 나머지는 특징), 장면은 영상 절반 이상에 공통으로 보이는 묶음을 모두 주제로 씁니다.
- **주제를 비우면** 올린 영상을 보고 비슷한 주제를 알아서 고릅니다. 파일 이름에 뜻있는 말이 있으면 그 말("손흥민 골 장면.mp4" → 손흥민, 카메라가 붙인 VID_·IMG_·KakaoTalk_ 같은 이름은 무시), 없으면 장면을 기기 안의 이미지 분류 모델(MobileNet v1, 약 5MB, 이때만 받음)로 보고 강아지·축구·바다·산·도시·공연 같은 넓은 주제로 묶습니다. 고른 주제로 비슷한 영상을 찾아 섞고, 결과 아래에 "고른 주제"를 보여 줍니다. 확신이 낮으면(20% 미만) 주제 없이 올린 영상만으로 만듭니다.
- **주제도 입력하면** 올린 영상을 모두 쓰고, 찾은 영상과 섞어 절반씩 나옵니다. 검색이 전부 실패해도 올린 영상으로 계속 만듭니다.
- 휴대폰·화면 녹화로 만든 WebM처럼 길이 정보가 없는 영상도 길이를 먼저 계산해서 씁니다.
- **주제와 함께 쓰면 서로 닮게** — 주제를 입력하고 영상도 올리면, 찾은 영상은 썸네일이 올린 영상과 닮은 순으로 먼저 쓰고(이미지 모델의 특징 벡터로 비교), 올린 영상 안에서는 찾은 영상들(주제)과 닮은 장면을 조금 더 높게 칩니다. 썸네일을 읽을 수 없는 출처는 그대로 둡니다.
- **가중치** — 올린 파일마다 ×1~×5를 고릅니다. **×1은 찾은 영상 하나와 같은 비중**이고 ×2는 그 2배입니다(예: 찾을 영상 4개 + 올린 영상 2개가 모두 ×1이면 영상마다 약 17%). 파일 옆에 편집에서 차지할 대략의 비율이 보이고, 편집할 때는 실제로 받은 영상 수로 다시 맞춥니다. 올린 영상만 쓰면 올린 영상끼리 가중치대로 나눕니다.
- **영상 찾지 않고 올린 영상만 편집**을 켜면 주제를 입력해도 영상을 검색하지 않습니다. 주제는 제목과 장면 판단(스포츠·인물 여부), "주제 edit" 스타일 학습에만 씁니다.
- 올린 영상은 기기 안에서만 쓰이고 서버로 보내지 않습니다. 제목 검사·관련성 검사는 건너뛰지만 장면 검열은 똑같이 합니다. 출처 표기(크레딧)에는 넣지 않습니다.

### 검색 결과가 없을 때

검색어 하나로 영상을 못 찾아도 멈추지 않고 넓혀 가며 다시 찾습니다.

1. **다른 검색어** — 주제의 관련 주제(소속 팀·그룹·종목 등)와 특징·분위기 키워드를 각각 주제로 찾습니다(예: "고양이"가 없으면 특징의 "바다").
2. **조건 풀기** — 그래도 없으면 검색에 걸렸지만 제목에 이름이 없어 뺐던 영상을 씁니다(부적절한 영상은 계속 제외).
3. **대상이 없을 때** — 특징·분위기에 스타일만 적었으면 분위기에 어울리는 영상(시네마틱 → 풍경, 하이프 → 익스트림 스포츠, 감성 → 노을, 레트로 → 도시 야경)으로 만들고, Wikidata에 없는 낱말도 그대로 검색합니다.

넓혀 찾았으면 결과 아래 **검색 넓히기**에 어떻게 찾았는지 알려 줍니다.

### 영상 수가 모자랄 때

영상 수를 여러 개로 골라도 제목에 주제 이름이 나오는 영상이 적으면, 남은 칸은 제목에 **관련 주제**(소속 팀·종목·그룹·대표작 등, Wikidata에서 가져옴)가 나오는 영상으로 채웁니다(이름이 나오는 영상이 항상 먼저). 결과 아래에 "영상 수 4개 중 3개를 썼어요 — 관련 영상 2개로 채웠어요"처럼 알려 줍니다. 아무 관련 없는 영상은 여전히 쓰지 않습니다.

### 검열

부적절한 단어나 영상은 쓸 수 없습니다.

- **입력 검사** — 주제·특징에 성적·욕설·혐오·잔혹·약물 관련 단어가 있으면 **생성 불가**로 버튼이 잠기고 이유가 표시됩니다. 주제가 가리키는 대상의 영어 이름·Wikidata 설명이 부적절해도(예: 성인물 배우) 생성 불가입니다. 띄어쓰기(`씨 발`), 기호(`씨.발`), 숫자 치환(`p0rn`), 초성(`ㅅㅂ`), 전각 문자 변형도 잡고, `시발점`·`강아지 새끼`·`Al Gore` 같은 멀쩡한 말은 막지 않습니다.
- **검색어 검사** — Wikidata에서 가져온 별칭·관련 주제에 금지어가 있으면 검색어로 쓰지 않고, Reddit은 성인 게시물을 빼고 검색합니다.
- **영상 정보 검사** — 영상 제목·채널·분류(Commons 분류, Internet Archive 주제어)에 금지어가 있으면 받지 않습니다.
- **장면 검사** — 영상마다 고르게 뽑은 장면 10개를 [NSFW.js](https://github.com/infinitered/nsfwjs)(MobileNetV2) 모델로 기기 안에서 분류해, 노골적인 장면이 하나라도 있거나 선정적인 장면이 둘 이상이면 뺍니다. 모델(약 3.5MB)은 처음 필요할 때만 받고, 검사가 실패하면 안전을 위해 그 영상을 뺍니다.
- **스포츠 영상** — 격투기·레슬링·수영처럼 맨살과 몸싸움이 많은 경기는 판별 모델이 자주 잘못 봅니다. 주제가 선수·팀·종목·리그이거나, 특징 문장이나 영상 제목·태그가 경기 영상(highlights, vs, 골, KO 등)이면 노출 판정을 하지 않고 노골적 판정 기준도 크게 높입니다(0.97 한 장면 또는 0.85 세 장면). 이렇게 걸린 영상은 그 영상만 빼고, 확실한 장면이 아니면 주제 전체 차단에는 세지 않습니다.
- **주제 단위 차단** — 한 주제로 찾은 영상의 30% 이상(최소 2개)이 검열 대상(금지어, 출처의 성인물 표시)이거나, 받아 본 영상 중 30% 이상(최소 2개)에서 부적절한 장면이 나오면 그 주제는 **생성 불가**가 됩니다. 우연히 섞인 1개는 그 영상만 빼고 계속 만듭니다.
- 제외된 영상은 "건너뛴 영상" 목록에 이유와 함께 표시됩니다. 자동 검사라 완벽하지 않을 수 있습니다. 금지어 목록은 `src/lib/moderation.ts`에서 고칠 수 있습니다.

### 편집 스타일 직접 정하기

특징 입력칸 아래 **편집 스타일** 칸에서 특징 문장으로 자동으로 정해진 값을 직접 바꿀 수 있습니다. 비워 둔 항목은 계속 자동입니다.

**자동 값은 특징·분위기 문장으로 정합니다.** 예: `긴장감 있고 웅장하게, 빠른 컷, 페이드 전환, 흑백, 슬로모션 없이, 빠른 비트`
- 분위기(하이프·시네마틱·감성·레트로) — "멋있게, 타격감, 소름, 긴장감, 부드럽게, 아련하게, 시티팝" 같은 표현도 알아듣습니다.
- 컷 속도("빠른 컷, 정신없게 / 천천히, 롱테이크"), 전환("페이드, 디졸브 / 휩 / 줌 펀치 / 하드 컷"), 색감, 효과, 템포("120bpm", "빠른 비트"는 +15)
- "~없이, ~빼고, no ~"는 그 효과를 뺍니다.
- **화면 느낌**: 밝고 청량한/어둡고 무거운(밝기·가장자리 어둡게), 강렬한/부드러운(대비), 화려한/물 빠진(채도), 몽환적인(빛 번짐), 긴장감(가장자리 어둡게)을 화면 보정으로 넣습니다.
- **흐름**: "점점 고조되게"는 본격적으로 터지는 지점(드롭)을 늦게(40%), "처음부터 터지게"는 일찍, "여운 있게"는 마무리를 길게 합니다(내 음악을 넣으면 음악의 드롭을 따름).
- **키워드**: 문장 속 내용 낱말(예: 골, 덩크, 무대)이 제목·태그에 나오는 영상을 먼저 쓰고, 골·슛·덩크·KO·태클·세이브 같은 결정적 동작은 그 순간이 있는 구간을, 세리머니·환호는 함성 속 사람이 보이는 순간을, 눈물·미소는 얼굴이 크게 보이는 순간을 우선합니다.
- **어떤 장면을 고를지**도 읽습니다: 밝은/어두운(밤), 격렬한/잔잔한, 함성·환호, 얼굴·클로즈업, 화려한, 그리고 찍힌 대상(바다·산·도시·자동차·무대·강아지 등 — 장면을 이미지 모델로 보고 그 대상이 보이는 장면을 우선). 격렬한 장면은 컷도 빠르게, 잔잔한 장면은 길게 합니다(컷 속도를 직접 말하면 그게 우선).
- 편집 스타일 칸을 펼치면 **특징에서 읽은 말**이 보이고, 각 칸의 "자동 (…)"에 그 결과가 나옵니다.

- **분위기** — 하이프·시네마틱·감성·레트로 등 (분위기에 맞는 기본 BPM·색감·효과도 함께 바뀜)
- **템포(BPM)** — 60~180, 비트와 컷 간격 기준 (내 음악을 넣으면 그 음악의 템포를 씀)
- **색감** · **컷 속도**(느리게/보통/빠르게) · **전환**(컷/페이드/휩/펀치 중 하나로 통일)
- **효과** — 칩을 눌러 켜고 끔 (파란 점 = 직접 바꾼 효과)
- **자동으로** 버튼으로 전부 되돌리고, 프리셋을 저장하면 이 설정도 함께 저장됩니다. 참고 에딧에서 배운 스타일보다 직접 정한 값이 우선합니다.

### 제목 · 텍스트

**제목 · 텍스트** 칸에서 영상 위 글자를 정합니다.

- **시작 제목** — 켜고 끌 수 있고, 제목을 직접 입력할 수 있습니다(비우면 주제 이름). 결과 파일 이름에도 씁니다.
- **부제목** — 제목 아래 작은 글씨입니다. 비우면 넣지 않고(예전처럼 편집 방식이 자동으로 붙지 않음), **편집 방식 넣기**를 누르면 지금 편집 방식(예: 하이프 · 빠른 비트 컷)을 채웁니다.
- **끝 출처(크레딧)** — 끄면 출처 화면(3초) 없이 마지막에 검게 페이드아웃합니다. 다른 사람의 영상을 쓰면 켜 두는 게 좋습니다.
- **텍스트 추가** — 최대 8개. 텍스트마다 시작 시각·보이는 시간(초), 위치(위·가운데·아래), 크기를 고릅니다. 앞뒤로 살짝 페이드됩니다.
- 직접 쓴 제목·텍스트도 금지어 검사를 하고, 프리셋에 함께 저장됩니다.

### 참고 에딧에서 스타일 배우기

**인터넷에서 "주제 edit" 찾아 배우기**를 켜거나 마음에 드는 에딧 영상(최대 3개)을 올리면, 그 에딧을 분석해 편집 스타일을 따라 합니다. 참고 에딧의 장면은 결과물에 쓰지 않고 스타일만 배웁니다.

- **컷 리듬** — 장면 전환을 촘촘히(0.1초 간격) 세어 샷 길이를 박자 단위로 바꾸고, 인트로·드롭·아웃트로 컷 패턴으로 씁니다.
- **템포** — 참고 에딧 음악의 BPM을 재서 비트와 컷 간격에 씁니다(내 음악을 넣었으면 내 음악 BPM 우선).
- **색감** — 채도와 색 기울기로 흑백·따뜻함·차가움·선명함을 고릅니다.
- **효과** — 흰 화면 번쩍임이 잦으면 플래시, 위아래 검은 띠가 있으면 레터박스, 컷이 아주 빠르면 흔들림·펄스·벨로시티, 느리면 슬로모션.
- 인터넷 검색은 Reddit(휴대폰에서는 막힐 수 있음)과 YouTube(로컬 도우미가 켜져 있을 때)에서 제목에 에딧 표시와 주제 이름이 있는 8초~3분 영상을 찾습니다. 참고 에딧도 검열을 거칩니다.

### 자연스러운 편집

팬 에딧에서 흔히 쓰는 기법을 무드에 맞게 넣습니다: 하이프는 드롭 컷마다 **줌 펀치**와 가끔 **휩**(가로 잔상), 컷 안에서 빨라졌다 느려지는 **벨로시티**; 감성은 **크로스페이드**; 시네마틱은 인트로·아웃트로 크로스페이드와 드롭의 휩. 줌은 부드럽게 가속·감속합니다. 특징에 `벨로시티`, `스피드 램프`를 적어 켤 수도 있습니다.

### 핵심 장면과 화면 비율 맞추기

- **자동 리프레이밍** — 분석할 때 장면마다 움직임과 사람(피부색)이 몰린 관심 지점을 찾고, 9:16·1:1처럼 비율을 바꿔 자를 때 가운데가 아니라 그 지점을 화면 가운데에 둡니다. 관심 지점은 컷마다 부드럽게 따라가고 영상 밖이 보이지 않게 막습니다.
- **인물이 보이는 순간 우선** — 주제가 사람·그룹(Wikidata의 사람, 직업이 있는 항목, 구성원이 있는 그룹, 스포츠 선수)이면 사람이 화면에 크게 나오는 순간의 하이라이트 점수를 높입니다.
- **화면 맞추기** (화면 비율 아래) — **자동**(기본): 꽉 채우면 원본의 60%도 안 보이는 영상(가로 영상 → 세로 화면 등)은 원본의 60%가 보이게 덜 자르고, 남는 곳은 같은 장면을 흐리게 깔아 채웁니다. **꽉 채우기**: 예전처럼 잘라서 채우고 주인공을 따라갑니다. **전체 보이기**: 자르지 않습니다.
- **검은 띠 제거** — 원본에 레터박스·필러박스(검은 띠)가 있으면 찾아서 잘라 내고 실제 화면만 씁니다.
- **카메라 이동 빼기** — 카메라가 선수를 따라가기만 해도 화면 전체가 바뀌어 움직임이 크게 잡히므로, 화면 전체의 이동을 빼고 남은 실제 동작으로 장면을 점수 매깁니다. 스포츠 영상은 펀치·슛 같은 결정적 순간이 있는 구간을 우선하고, 걷기·세리머니·견제만 하는 구간은 뒤로 미룹니다.
- **결정적 순간 살리기** — 움직임과 소리가 갑자기 확 튀는 순간(펀치가 꽂힘, 슛, 덩크, 착지)을 찾아, 그 순간이 컷 중간의 박자에 오게 장면을 잡습니다. 주먹을 내지르기 직전에 다음 컷으로 넘어가지 않고 준비 동작과 맞은 뒤 반응까지 보입니다. 계속 이어지는 동작의 시작처럼 앞이 그냥 빈 장면이면 옮기지 않습니다.
- **영상 전체가 살아 있는지** — 장면 점수는 영상 안에서 상대적으로 매기므로, 영상끼리도 비교합니다. 카메라 이동을 뺀 실제 움직임·멈춘 비율·빈 화면 비율로 영상 전체의 살아 있는 정도를 재서, 거의 내내 멈춘 영상(사진 모음·슬라이드쇼·배경화면 영상)은 다른 후보가 있으면 건너뛰고(칸이 끝내 모자라면 마지막에 씀), 덜 살아 있는 영상은 같은 주제 안에서 덜 나오게 합니다(최소 30%). 직접 올린 영상은 그대로 씁니다.
- **의미 없는 장면 거르기** — 거의 내내 멈춰 있는 구간(정지 화면·자막 카드·슬라이드)과 단색·뿌연 화면은 점수를 크게 낮추고, 같은 영상에서 가장 좋은 장면보다 많이 떨어지는 구간은 채워 넣지 않습니다(장면이 모자라면 좋은 장면을 다른 지점부터 다시 씀).

### 배경음악 스타일

배경음악 칸에서 **자동(분위기 따라) · 하이프·트랩 · 시네마틱·웅장 · 감성·피아노 · 레트로·신스웨이브** 중 고를 수 있습니다. 자동 작곡은 만들 때마다 조·화음 순서·드럼 무늬·짧은 멜로디가 바뀌어 매번 다른 곡이 됩니다(분위기·템포·드롭 위치는 그대로). **무료 음악 찾기**를 고르면 직접 작곡하는 대신 [Openverse](https://openverse.org)(Jamendo·Freesound·ccMixter 등 CC 라이선스 음원 모음)에서 고른 스타일에 맞는 곡을 찾아 쓰고, 내 음악처럼 박자·드롭을 분석해 컷을 맞춥니다. 편집(자르기)이 허용된 라이선스만 쓰고, 곡 정보는 결과 아래와 끝 출처 화면 맨 위에 들어갑니다(CC BY는 출처 표기가 조건이니 끝 출처를 켜 두세요). 곡을 못 받으면 자동 작곡으로 만듭니다. 같은 곡이 계속 나오지 않게 분위기마다 여러 검색어·페이지 중에서 무작위로 찾고, 최근에 쓴 곡(30곡)은 뒤로 미룹니다. SoundCloud는 새 API 등록을 받지 않고 약관상 곡을 내려받아 편집에 쓸 수 없어 연동하지 않습니다. 템포를 직접 적거나(`120bpm`) 참고 에딧에서 배우지 않았다면 고른 장르의 기본 템포로 컷도 맞춥니다. 내 음악 파일을 넣으면 그 음악을 씁니다. 프리셋에도 저장됩니다.

### 프리셋

위쪽 스토리 줄에서 **프리셋 저장(+)**을 누르면 지금 입력한 주제·특징·길이·화면 비율·영상 수·라이선스 설정을 이름을 붙여 저장합니다. 스토리를 누르면 그 설정을 한 번에 불러오고, 지금 입력과 같은 프리셋은 그라데이션 테두리로 표시됩니다. 직접 만든 프리셋은 ×로 지울 수 있습니다(기본 프리셋은 고정). 프리셋은 이 브라우저에만 저장됩니다.

만드는 도중이나 다 만든 뒤에 입력을 바꿔도 게시물의 제목·설명·해시태그와 화면 비율은 만들기를 누른 순간의 설정을 그대로 보여 줍니다.

### 여러 주제 섞기

주제 칸에 쉼표로 여러 주제를 넣으면 주제마다 따로 영상을 찾아 하나의 에딧으로 합칩니다. `N:단어:`라고 쓰면 그 주제가 N배 비중으로 들어갑니다(0.1~10배, 최대 6개 주제).

```
손흥민, 3:케인:, 토트넘   → 손흥민 20% · 케인 60% · 토트넘 20%
```

- 받을 영상 수를 비중대로 나누고, 주제마다 최소 1개는 받습니다(주제가 많으면 영상 수를 최대 8개까지 늘림).
- 편집할 때도 컷이 비중대로 나오도록 섞습니다. 어떤 주제의 영상이 모자라면 남은 자리는 다른 주제가 채웁니다.
- 입력하는 동안 주제별 비중(%)이 미리 보이고, 결과 카드에는 어느 주제에서 찾은 영상인지 표시됩니다.

### 특징 키워드 예시

| 분류 | 키워드 |
| --- | --- |
| 분위기 | 신나는·빠른·하이프 / 시네마틱·웅장 / 잔잔·감성 / 레트로·빈티지 |
| 색감 | 따뜻한, 차가운, 흑백, 네온·선명한, 틸 |
| 효과 | 플래시, 흔들림, 줌, 글리치, 슬로우모션, 그레인, 레터박스, 깔끔하게(효과 줄이기) |
| 템포 | `120bpm`처럼 직접 지정 |
| 장면 | 골, 경기, 무대, 춤, 발사, 우주, 바다, 도시 등 → 검색어에 반영 |

## 개발

```bash
pnpm install
pnpm dev      # 개발 서버
pnpm test     # 단위 테스트
pnpm build    # 타입 검사 + dist/ 정적 빌드
```

Node.js 22+, pnpm 10+. 최신 Chrome · Edge · Firefox 데스크톱을 권장합니다(렌더링에 `MediaRecorder`, Web Audio 사용). 렌더링은 실시간으로 진행되므로 그동안 탭을 띄워 두세요.

### 휴대폰에서 쓰기

https://editmatker.vercel.app 을 휴대폰 브라우저로 열면 바로 됩니다. 휴대폰에서는 로컬 도우미를 실행할 수 없으므로 **YouTube 없이** Reddit · Wikimedia Commons · Internet Archive · 스톡 영상(Pexels·Pixabay·Mixkit)에서 영상을 찾습니다.

- Reddit은 휴대폰 브라우저에서 직접 검색하고, 막히면 Vercel 함수(`api/reddit.ts`, `api/media.ts`)를 거쳐 다시 시도합니다.
- 작업하는 동안 화면이 꺼지지 않게 하고, 끝나면 **공유 · 사진에 저장** 버튼으로 사진 앱이나 SNS로 바로 보낼 수 있습니다.
- 메모리를 아끼려고 영상 수(최대 4개)와 파일 크기(60MB)를 줄여서 씁니다. 렌더링은 실시간이니 끝날 때까지 화면을 켜 두세요.
- Vercel에서 Reddit 검색이 자주 막히면 [Reddit 앱](https://www.reddit.com/prefs/apps)(script 유형)을 만들고 Vercel 프로젝트 **Settings → Environment Variables**에 `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`을 넣으세요. 그러면 공식 API로 검색합니다.

### YouTube 로컬 도우미 (PC 전용)

브라우저는 보안 정책(CORS) 때문에 YouTube 영상 파일을 직접 받을 수 없습니다. 그래서 내 컴퓨터에서 작은 도우미 서버를 켜면, 도우미가 [yt-dlp](https://github.com/yt-dlp/yt-dlp)로 영상을 받아 웹앱에 넘겨 줍니다. 도우미가 없으면 YouTube 없이 Reddit 영상(소리 없는 파일)과 Commons·Internet Archive만 씁니다.

1. yt-dlp와 ffmpeg 설치
   - macOS: `brew install yt-dlp ffmpeg`
   - Windows: `winget install yt-dlp.yt-dlp Gyan.FFmpeg`
   - Linux: `pipx install yt-dlp` 후 배포판 패키지로 `ffmpeg` 설치
2. 저장소를 받아 도우미 실행
   ```bash
   git clone https://github.com/jdjdjehejehejd-bot/editmatker.git
   cd editmatker
   pnpm install && pnpm build
   pnpm helper
   ```
3. https://editmatker.vercel.app 에서 **YouTube 연결**을 누르거나, 도우미가 띄운 http://localhost:8787 을 엽니다. 브라우저가 "로컬 네트워크 접근"을 물으면 허용하세요. Safari는 공개 사이트에서 localhost 접속을 막으므로 http://localhost:8787 을 쓰세요.

도우미는 내 컴퓨터(127.0.0.1)에서만 열리고, editmatker 웹앱 주소에서 온 요청만 받으며, YouTube·Reddit 주소만 내려받습니다. 받은 영상은 임시 폴더에 2시간 동안 캐시됩니다. YouTube가 "로봇이 아닌지 확인"을 요구하면 `EDITMATKER_YTDLP_ARGS="--cookies-from-browser chrome" pnpm helper`처럼 브라우저 쿠키를 쓰게 할 수 있습니다.

### 배포

Vercel에 연결되어 있어 `main` 브랜치에 푸시하면 자동으로 배포됩니다(다른 브랜치·PR은 미리보기 배포). Vercel이 Vite 프로젝트를 자동 인식하므로 별도 설정 없이 `pnpm build` 결과물인 `dist/`를 그대로 올립니다.

## 권리 안내

- **모든 공개 영상** 모드로 만든 결과물에는 YouTube·Reddit 영상처럼 재사용 허가가 없는 영상이 들어갑니다. 개인 감상은 괜찮지만, 공개적으로 올리거나 상업적으로 쓰려면 원작자 허락이 필요할 수 있습니다. YouTube 약관은 영상 내려받기를 제한하므로 도우미 사용은 본인 책임입니다. 자유롭게 공유하려면 **재사용 가능만**을 고르세요.
- 라이선스·작성자 정보는 업로더가 입력한 메타데이터이며 앱이 법적 정확성이나 인물의 초상권 등을 검증하지 않습니다. 공유 전에 크레딧의 원본 페이지를 확인하세요.
- 어떤 모드든 CC BY / CC BY-SA 영상은 저작자 표시가 필요합니다(크레딧 카드와 편집 계획 JSON에 자동 포함). CC BY-SA 자료가 들어간 결과물은 같은 조건으로 공유해야 합니다.
- 영상은 브라우저 메모리(도우미를 쓰면 내 컴퓨터의 임시 폴더)에서만 처리되며 어디에도 업로드되지 않습니다.
